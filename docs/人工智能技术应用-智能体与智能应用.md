# 人工智能技术应用：智能体与智能应用

> 以「AI 李老师」为例——高校数字治理科研团队的数字分身实践

---

## 导言

大模型解决的是「生成」问题，智能体（Agent）解决的是「完成任务」问题，智能应用（Intelligent Application）解决的是「让这件事稳定地服务于人」的问题。三者是递进关系：模型是能力底座，智能体是能力的组织方式，智能应用是能力的交付形态。

本文分两个板块展开：

- **上篇 · 智能体**：AI 李老师是什么、由哪些能力构成、如何思考与行动、如何被评价；
- **下篇 · 智能应用**：AI 李老师如何从一套代码变成可访问、可运营、可治理的产品。

---

# 上篇 · 智能体：AI 李老师

## 一、智能体的四个要件

一个只会在对话框里答题的模型，是「聊天应用」；一个能读懂 68 份论文指导资料、检索出对应章节、按学术规范组织答案、并主动标注出处的系统，才是「智能体」。差别不在模型参数，而在模型之外多出来的四件事：

1. **感知**：能读取外部世界——文档、网页、数据库、用户输入；
2. **记忆**：能记住领域知识与历史交互，而不是每次从零开始；
3. **规划**：能把模糊需求拆成步骤，决定「先查什么、再做什么」；
4. **行动与反思**：能调用工具改变外部状态，并能检查、修正自己的输出。

AI 李老师正是按这四个要件搭起来的。

## 二、AI 李老师是谁

### 2.1 角色定位

AI 李老师不是通用问答机器人，而是高校数字治理科研团队「数字人（数字分身）」项目中的**学位论文指导分身**。它的职责边界很清晰：把一位导师关于选题、文献综述、研究方法、开题答辩、学位论文规范的经验，转化为可随时访问、可追溯来源的对话服务。

项目把数字分身的能力拆成四个场景：

| 场景 | 目标用户 | 核心诉求 |
|---|---|---|
| 研究项目解释 | 学生 | 解释研究项目在做什么，降低理解门槛 |
| 前沿热点推理 | 研究团队 | 研判数字治理领域的研究前沿 |
| **学位论文指导** | 研究生 | 提供规范的论文指导，保障学术质量 |
| 学术沟通渠道 | 其他老师 / 智能体 | 跨主体的学术交流 |

AI 李老师当前落地的是第三个场景，也是需求最刚性、最容易验证效果的一个——论文指导有明确的对错、有稳定的资料源、有可量化的评估标准。

### 2.2 它的知识来自哪里

AI 李老师的「学识」不是模型预训练里的通用知识，而是一个专门的资料库 nlp_/，共 **68 个内容文件**，覆盖六类内容：

- **典型问题与期望回答颗粒度**：定义了「答到什么程度算合格」；
- **论文写作、文献综述、选题、开题报告**：写作方法论；
- **答辩点评与问答集合**：真实答辩现场的问题与点评，可直接作为评估测试集；
- **研究方法**：扎根理论、案例研究、访谈方法，以及学位论文规范；
- **制度依据**：学位法、研究生学科专业简介与学位基本要求。

格式上包含 44 个 PDF、17 个 .doc、6 个 .docx、1 个 .ppt。这带来第一个工程问题：**异构文档的解析**。系统的做法是按能力探测选择后端——PDF 用 pymupdf 逐页抽取，.docx 用 python-docx 读正文与表格，.doc 在 Windows 上走 Word COM 自动化、其他平台走 LibreOffice 转换，扫描件则用 RapidOCR 兜底。缺少解析后端时不会静默跳过，而是在建库开始时打印可用性清单，把「隐性失败」变成「显性告警」。

最终，这 30 个有效来源被切成 **5125 个语义块**，进入向量库。

### 2.3 它在服务谁：真实使用画像

这一点最能说明智能体的价值——它不是实验室演示，而是有真实使用数据的生产系统。项目评估了 data_benchmark/ 下 6 个月（2025-10 至 2026-03）的对话导出，共 **4032 条**真实问答：

| 维度 | 数据 |
|---|---|
| 智能体构成 | AI 李老师 3626 条（90%）、AI 南大政管院 406 条（10%） |
| 独立用户 | 236 人；其中 161 人提问 ≥2 次 |
| 地域 | 21 个省份、34 个城市；内蒙古 810、江苏 649、吉林 530、上海 409，另有吉隆坡 297 条海外提问 |
| 使用时段 | 集中 10:00–16:00，凌晨极少 |
| 主题 | 539 个主题，top 5 仅占 16%，长尾极长 |

这组数字说明三件事：**第一，AI 李老师承担了绝大部分实际服务量**，是这个数字人体系里的主力；**第二，用户需求高度分散**，539 个主题、没有单一话题超过 16%，靠「预设问答对」覆盖不了，必须依赖检索；**第三，服务半径远超一个课题组**，从江苏到内蒙古、从澳门到吉隆坡，「数字分身」确实突破了物理空间。

它的**回答形态**同样值得注意：答复中位数 409 字、平均 671 字、P90 达 1268 字。这不是「一句话客服」，而是段落级的专家答复——有结论、有依据、有建议。这正是「导师分身」应有的样子。

## 三、智能体的能力结构：五层拆解

把 AI 李老师拆开看，它是一个典型的「检索增强生成 + 工程化服务」智能体。整条链路分七层，对应智能体的五种核心能力。

### 3.1 感知层：把非结构化资料变成可计算文本

解析层负责「读懂」各种格式，并统一输出 text / source / category / ext 四元组。两个容易被忽略的设计：

- **单文件失败不拖垮全局**：每个文件独立兜底，坏的进跳过清单，好的继续入库；
- **元数据即检索维度**：category 从目录结构推导（如 006/研究方法/扎根理论），后续可直接用于「只在研究方法类资料里检索」。

对智能体而言，感知不是「能读文件」，而是「读完以后知道自己读的是什么」。

### 3.2 记忆层：分块、向量化与持久化

知识进入记忆要经过三步：

1. **分块**：先按空行拆段，识别标题（一、/（一）/第X章/文献综述 等章节词），再按句子边界累积到 600 字，相邻块保留 100 字重叠，防止语义被硬切断。每块携带 section 元数据，回答时能定位到具体小节。
2. **向量化**：本地 BAAI/bge-m3，1024 维，归一化后用余弦距离。选本地模型是为了离线、免费、中文效果好，且数据不出内网。
3. **入库**：Chroma 持久化，主键采用「路径哈希 :: 文件名 :: chunkN」。这个设计解决了一个真实踩过的坑——两个不同目录下有同名文件（文献综述写作方法_法学.doc），用文件名做主键会互相覆盖。主键唯一性不是洁癖，是知识库正确性的底线。

此外还有**向量缓存**：以「文件集合 + 模型 + 分块参数」做签名，资料没变时重建直接复用，避免每次 30–40 分钟的重复计算。

### 3.3 规划层：先想清楚「该查什么」

用户的问题往往不适合直接拿去检索。实测里提问两极化严重：约 59% 短于 50 字，但有 3.6% 超过 2000 字，用户把大段研究背景塞进问题里。直接拿长文本做向量检索，噪声极大。

于是规划层提供两种查询增强（默认关闭，按需开启）：

- **查询改写**：让 LLM 把口语化、带大量背景的问题压缩成 60 字以内、术语准确的检索式。例如把「我做的这个 HPV 疫苗换选题的事情……」改写成「HPV 疫苗 政策执行 选题 可行性 研究设计」。
- **HyDE**：先让模型写一段「看起来像标准答案」的 150 字假设段落，再用它去检索。因为答案和答案在向量空间里更接近，比问题和答案更接近。

这两个动作的本质，都是智能体在「行动之前先规划」——不是拿到问题就查，而是先决定「用什么查询去查」。

### 3.4 行动层：混合检索 + 重排序 + 上下文组装

这是 AI 李老师「查得准」的核心。

**双路召回**：稠密向量负责语义（「开题要做什么」能匹配到「开题报告内容要求」），BM25 负责精确词（「扎根理论」「三级编码」这类术语，向量反而容易漏）。两路各取 20 个候选，用 **RRF** 融合：

~~~
score(d) = Σ_i 1 / (k + rank_i(d))    // k = 60
~~~

RRF 的好处是不需要归一化两路分数量纲，只看排名，工程上稳健。

**重排序**：融合后用 bge-reranker-v2-m3 交叉编码器对候选逐对精排，专治「召回到了但排得不对」。因模型约 2.3GB、CPU 推理慢，默认关闭、懒加载，需要时再开。

**父子分块**：子块（600 字）入库用于精准检索，父块（1500 字）存在 sidecar 文件里。命中子块后按偏移量换回父块上下文再送给模型——检索要「准」、生成要「全」，这两个目标天然冲突，父子结构是解法。

**上下文治理**：检索回来 4 个片段不等于 4 个都该塞进去。系统按余弦距离阈值过滤噪声（至少保留 1 条），并在评测中对比 top-k 的影响。喂给模型的上下文，干净比多更重要。

### 3.5 反思层：让智能体知道自己答得好不好

没有评估的智能体只是「看起来能用」。评测闭环分两条线：

**检索指标**：用评测集里的改写问题 + 答案定位金标块，比较 BM25 与 BGE-m3 的 Recall@k、MRR@k、nDCG@k。

**答案质量**：把 4032 条真实对话清洗、切分成 train/test，逐条跑「检索 + 生成」，再用 **LLM-as-judge** 按 1–5 分打分（5=完全覆盖要点，1=错误或无关），无 LLM 时降级为字符 bigram F1 与 ROUGE-L 基线。

这里有一个非常关键的方法论细节：**按用户分组切分**。数据显示前 5 名用户贡献约一半样本，user_JuHAw 一人就问了 676 次，而同一用户的问题高度同质。如果随机切分，同一个人的相似问题会同时出现在训练侧和测试侧，模型等于「背答案」，分数虚高。所以切分规则是：

- 同一用户的全部问答不跨池；
- 语义近重复聚簇，同簇不跨池；
- 按「智慧员工 + 主题」分层抽样，test 约 8%；
- 固定随机种子 42，保证可复现。

还额外引入 MAX_SOURCE_SHARE 约束：单个来源是不可再分的最小单元，本库最大一位专家占 16.9%，一旦整户进 test 比例必然突破 10%，所以超限来源整户留在 train。最终 3902 条 → train 3557 / test 345（8.84%），234 个来源中 4 个被排除，**train/test 来源零交集**。

这条规则看似是评测细节，实则是智能体可信度的根基：**一个靠泄漏刷出来的高分，比低分更危险**。

## 四、智能体的行为特征：一个有边界感的专家

真正专业的智能体，价值不仅在于「会答」，更在于「知道什么时候不该答」。

### 4.1 强约束的人设

系统提示词明确要求：

- **只依据给定资料回答**，不做模型自由发挥；
- **必须用 [来源N] 标注出处**，让每个结论可追溯；
- **资料不足时明确说明不足**，而不是编一个像样的答案；
- 使用中文，条理清晰、准确。

这套约束把 AI 李老师从「什么都懂的聊天机器人」改造成「只对资料负责的助教」。对学术场景而言，后者才是可用的——学生需要的不是「听起来对」，而是「有依据」。

### 4.2 输出结构

结合 409 字的中位答复长度与学术指导场景，AI 李老师的目标输出结构是：

**结论 → 依据（引用来源）→ 建议（可执行动作）**

例如问「文献综述怎么写」，理想的回答不是罗列定义，而是先给出「综述要围绕研究问题组织，而非按时间罗列文献」这一结论，再引用资料库中的写作方法条目，最后给出「先建文献矩阵、再聚类主题、最后写述评」的操作建议。

### 4.3 能力边界

它明确不做什么：不代写论文、不提供资料库之外的政策解读、不对未收录的学科规范做猜测。这种「能力边界」不是缺陷，而是智能体可信度的一部分。一个敢于说「资料不足」的智能体，比一个永远自信的智能体更接近专家。

## 五、从单智能体到多智能体

当前的 AI 李老师是「单智能体 + 单知识库」，但架构已经为扩展留好了接口。

### 5.1 双轨标注：机器智能 + 专家智能

当前是机器标注（自动切块、向量、元数据）。下一步打通专家标注：

- 按块 id 增删改（id 形如 路径哈希 :: 文件名 :: chunkN）；
- 在元数据中增加 expert_tag、quality、difficulty 字段，检索时用条件过滤；
- 专家标注另存 annotations.jsonl，与向量库通过 id 对齐，不破坏自动建库流程。

这是「人类在环」（Human-in-the-loop）的具体落地：机器负责规模，专家负责判断。

### 5.2 分身矩阵

数据里已经出现了第二个智能体——**AI 南大政管院**（406 条，10%）。这说明平台本身就是多分身并存的。未来的形态不是「一个万能智能体」，而是「一个分身矩阵」：论文指导分身、项目解释分身、政策研究分身，各自有知识边界，通过统一的路由层协作。用户问「这个选题的政策背景和论文规范分别是什么」，可以由两个分身分别回答再汇总。

# 下篇 · 智能应用：从能力到服务

智能体证明「能不能做」，智能应用解决「能不能用、能不能长期用、能不能放心用」。这一篇讲 AI 李老师如何被交付出去。

## 六、应用的三种形态

### 6.1 三种入口，一套内核

- **CLI**：python -m rag.cli ask 「扎根理论的三级编码是什么？」，适合调试与批量评测；
- **REPL 常驻服务**：模型与向量库只加载一次，消除每次约 18 秒的重载开销；
- **HTTP 服务**：FastAPI 暴露 GET /health 探活与 POST /ask 提问。

三种入口共用同一个 RAGService，避免逻辑分叉——这是应用可维护性的基础。

### 6.2 面向真实用户的 Web 界面

rag/web/ 下是一个轻量对话界面：顶部有连接状态指示灯，欢迎页给出三个示例问题（「扎根理论的研究程序是什么」「开题阶段要完成什么」「文献综述应该怎么写」），输入框支持回车发送、Shift+回车换行，还可以选择检索片段数 2/4/6/8。

界面克制，但把「检索片段数」这个参数暴露给用户，实际上是在让用户参与智能体的决策——这是一种很实用的可解释性设计。用户能感知「答案是由几段资料支撑的」，信任感随之建立。

### 6.3 容器化交付

项目提供 Dockerfile 与 docker-compose.yml：容器化运行、restart: unless-stopped、模型缓存挂载到独立 volume、内存限制 5GB、健康检查 30 秒一次、日志滚动 10MB×3。

这些不是「炫技」，而是智能应用从「能跑」到「能长期跑」的分界线：模型文件不随容器重建丢失，进程崩溃能自愈，内存不会拖垮宿主机，日志不会写满磁盘。

## 七、应用场景的扩展路径

四个场景共用一套「解析—分块—向量化—检索—生成—评测」框架，只需替换资料源与提示词：

| 场景 | 数据源 | 能力要求 |
|---|---|---|
| 学位论文指导（已落地） | 论文写作、研究方法、答辩资料 | 检索 + 生成 + 引用 |
| 研究项目解释 | 项目文档、申报书、结题材料 | 检索 + 摘要 + 通俗化 |
| 前沿热点推理 | 文献、政策文本、行业报告 | 多步检索 + 推理链 + 反思 |
| 学术沟通渠道 | 对外知识接口 | 标准化协议 + 权限控制 |

其中「前沿热点推理」的门槛最高：它不是单轮检索能解决的，需要多步检索、证据汇聚、结论反思，属于更接近「规划型智能体」的形态。这也是后续架构演进的重点。

## 八、智能应用的数据闭环

智能应用与一次性 Demo 最大的区别，是它能从使用中学习。AI 李老师的闭环由四段构成：

**真实对话 → 清洗切分 → 评测反馈 → 检索与提示词调优**

- **真实对话**：4032 条生产数据，是模型效果的唯一真相来源；
- **清洗切分**：去 BOM、去首尾 `...`、过滤 <5 字提问与 <20 字答复、按用户分组切分；
- **评测反馈**：检索指标（Recall/MRR/nDCG）+ 答案质量（LLM 评委 + 词法基线）+ 消融对比（dense / hybrid / hybrid+rerank / hybrid+改写）；
- **调优**：基于评测结果扫 CHUNK_SIZE、FETCH_K、RRF_K、rerank 组合。

这条闭环让「优化」不再是拍脑袋，而是有对照、有回归、有可复现的实验。

## 九、智能应用的工程健壮性

真实数据比任何演示都诚实。4032 条对话暴露了四类问题：

| 问题 | 数据表现 | 设计启示 |
|---|---|---|
| 用户高度集中 | 前 5 用户占约一半，最高一人 676 条 | 评测必须按用户分组，否则严重泄漏 |
| 导出脏数据 | 15%（598 条）答复以 ... 开头 | 数据清洗要作为流水线的一等公民 |
| 无效样本 | 121 条提问 <5 字、9 条答复 <20 字 | 评测前过滤，避免均值被稀释 |
| 多轮上下文缺失 | 无会话 id，一问一答独立存储 | 单条打分可接受，但要知道这是局限 |

还有两个「沉默的坑」，它们直接决定了应用能否长期运行：

- **文件名乱码**：从 GBK 环境解压的 zip 会让中文名变成乱码，系统在建库前检出异常字符直接报错，并把 72 个损坏文件名按 UTF-8 → CP437 无损回转；
- **空库风险**：建库前先快照现有库（保留最近 2 份），写失败自动回滚；资料目录不存在或没有可入库文件时直接报错退出，而不是静默生成一个空库。

这两条体现的是同一个原则：**宁可显性失败，不可静默降级**。知识库类应用最危险的故障不是报错，而是「看起来正常但答得不对」。

## 十、风险与治理

智能应用越接近真实业务，越要正视风险。

1. **幻觉**：即使有 RAG，模型仍可能把检索片段拼接成资料中没有的结论。对策是强约束提示词 + 来源标注 + 资料不足明说，三管齐下。
2. **评测主观性**：LLM-as-judge 本身有模型偏好，词法基线在长答复上系统性偏低。结论应作相对比较（A 方案 vs B 方案），而非绝对结论。
3. **数据泄漏**：不仅是 train/test 泄漏，还包括测试题混入检索库或 few-shot 记忆库。测试池必须从「所有会被模型检索到的数据库」里物理隔离。
4. **隐私**：对话数据含用户姓名与地域，导出与评测需脱敏；向量化与生成尽量走本地或可信内网。
5. **成本**：重排序模型 2.3GB、BGE-m3 建库 30–40 分钟、每次查询若走 HyDE 要多一次 LLM 调用。默认关闭、按需开启的 opt-in 设计，是对成本的尊重。

## 十一、结语：智能体决定上限，智能应用决定价值

回看 AI 李老师，它没有惊人的参数规模，也没有炫目的多模态能力。它的价值来自两组朴素的工程选择。

**智能体侧**——把 68 份资料认真解析、切块、向量化，而不是直接丢给模型；用混合检索补上单一向量的盲区，用重排序修正排序；用父子分块平衡「检索要准」与「生成要全」；用来源标注和「资料不足就明说」守住学术场景的底线。

**智能应用侧**——用三种入口覆盖调试、常驻、对外服务；用严格切分保证评测分数不自欺欺人；用快照、回滚、脏数据检测保证系统长期可用；用容器化与健康检查保证服务不中断。

智能体的终点不是「像人一样聊天」，而是「在特定领域里，可信地完成一件具体的事」。AI 李老师完成的这件事，是让每一位学生，无论身在内蒙古、澳门还是吉隆坡，都能随时得到一次有依据、有出处、有建议的论文指导。

**智能体决定了一个应用的上限，智能应用决定了这个上限能被多少人用到。** 这大概就是「数字分身」最实际的意义。
