- 启动时解析 docx，结果缓存成 JSON（放在 docx 同目录，`<docx 名>.<库名>.cache.json`），**源文件的修改时间或大小变了就自动重新解析**；缓存坏了也只是重新解析。
- 某个 docx 不存在 → 只跳过那个库（日志一行“xx库未启用”），服务和其它路由照常启动。
- 模型分工：选案 / 挑段 / 选块用 **Flash、关闭思考**；判例作答、政策作答用 **Pro、思考 low**；temperature 一律 0；全部走胜算云（`COURSE_LLM_*`），**不用**论文库的 `LLM_API_KEY`。
- 路由：政策库为真实路由，可与课程 / 判例 / 名言两两组合（最多 2 个）；“尚未上线”占位已删除；名言类问题（“给我一句名人名言”）归名言库，库里没有就回答“合集中没有找到相关表述”，不再拒答。
- 课程回答附带的“巩固练习”只给判断题和名词解释，没有符合的题时不显示这一块。
- 测试：全量 `952 passed, 1 skipped`；`API_KEYS=x` 同样 `952 passed, 1 skipped`（全部 mock，无任何真实调用）。

## 5. 重启服务

先 `pkill`，再用 **`API_KEYS=`（置空）** 和 `nohup` 启动，日志写到 `/root/futurx_serve.log`：
```bash
pkill -f "rag.cli serve --http --host 127.0.0.1 --port 8000"
sleep 2
pgrep -af "rag.cli serve" || echo "旧进程已退出"

cd /home/FUTURX
API_KEYS= nohup python -m rag.cli serve --http --host 127.0.0.1 --port 8000 > /root/futurx_serve.log 2>&1 &
sleep 40                                   # 论文库 + 课程库 + 试卷库 + 三个 docx 库的加载
tail -n 30 /root/futurx_serve.log
```
- **首次启动要多解析三份 docx**：本地实测 判例库约 1.4 秒、名言库约 0.1 秒、政策库约 2.3 秒，合计约 **4 秒**；服务器 CPU 较慢时按 2–3 倍估计也就十来秒，包含在上面 `sleep 40` 里。第二次起读 JSON 缓存，更快。
- 端口 **8000** 是原有端口，没有新增端口；服务绑定 `127.0.0.1`，由你原有的反代对外。
- 某个库的 docx 缺失 / 解析失败**不会拖垮服务**：日志里会有一行“判例库未启用… / 名言库未启用… / 政策库未启用…”，其余路由照常。
- 日志里**不应出现**任何 key；若出现请告诉我。
- 内存：三个库都在内存里只放文本和 BM25 倒排索引（政策库约 3455 块），**不加载任何模型**，增量很小（估计几十 MB，未在服务器实测）。

每一条检查：①首个事件是 `route`，`routes` 与预期一致；②最后是 `done`，无 `error`；③判例答案前两行是程序填的，不是模型生成；④名言题只有「」原文加出处，无任何解读；⑤政策题每个要点都有 `[n]`，来源是“篇 › 文件名 › 第X条”，若引用了征求意见稿，正文和来源里都有“征求意见稿，非正式生效文本”；⑥组合题末尾有一句问句。

## 我没验证、需要你留意的

1. **没有任何真实调用**：选案 / 挑段 / 选块的实际准确度（Flash 能否在 12–15 个候选里选对）、作答效果、组合回答的表现，都只在 mock 下验证过。上线后用第 6 步的几道题人工看一眼，尤其是**政策题的引文是否逐字**、**判例头部是否正确**、**政策答案的条号是否对得上**。
2. **BM25 的召回上限**：候选只来自关键词检索，问法与条文用词差距大时（比如口语化）可能一个都不沾边，此时靠模型给出的改写词重查一次；仍然没有就回答“没有找到”。点名（文件名 / 简称 / “数据二十条”等别名）与点条（“第二十一条”）不受此影响。
3. **政策汇编里日期多数为空**：只有 17 个文件开头有“（…通过 / 公布）”括号注，其余发布日期按设计留空，不猜。回答里不会出现这些文件的日期。
4. **非条款式文件（意见、规划、白皮书）没有“条”**：这类文件的引用只写到文件名，来源形如“篇 › 文件名”；问“数据二十条第五条”会因找不到第五条而回退为在该文件内检索。
5. **政策库里有 8 个征求意见稿**：回答和来源里程序会标“征求意见稿，非正式生效文本”，并在末尾附“以汇编收录版本为准，现行有效性请以官方发布为准。”
6. 判例点名直达的别名是程序从案名 / 案号自动提取的，47 个案里有 8 个没有任何别名（案名全是“某”“甲公司”之类匿名），这些案只能靠检索命中，不能点名。
7. 评测集里补的 25 + 20 道路由题**没有跑过真实模型**，规则兜底在上面全对，模型路由的准确率未知。
