# FUTURX 架构总览

面向高校数字治理科研团队的**数字人（AI 李老师）**。一个 HTTP 入口后面挂 6 个知识库，外加一条不检索的大模型兜底路径和一条零调用的自述路径。

本文是当前代码（`c9455c7`）的实际形态，不是规划稿。凡写「实测」的地方，都是在本机对 8001 端口跑出来的结果。

## 2. 一次提问的完整链路

```
用户输入
  │
  ├─① 入口        POST /auto/ask  或  /auto/ask/stream（网页走流式）
  │
  ├─② 取历史      会话库最近 6 轮 / 8000 字
  │
  ├─③ 身份识别    student.parse + parse_title → 写 profile
  │                └ 纯自述（「我是本科生 编辑出版专业」）→ 回一句确认，零调用，结束
  │
  ├─④ 追问改写    _standalone_question → routed_q
  │                └ 仅当 ≤20 字或含「这/那/它/第二种」才改写；长句原样
  │
  ├─⑤ 题库预匹配  _prematch_with_history（纯程序，零模型调用）
  │                └ 命中 → 直接给「题目 + 参考答案 + 解析」，结束
  │
  ├─⑥ 路由        classify(routed_q) 一次 LLM 调用；失败回落关键词规则
  │
  ├─⑦ 分发作答    见第 3 节
  │
  └─⑧ 收尾        追问生成 / 画像回写 / 问答记录落库
```

### 两个问题的用法区别

| 变量 | 用途 |
|---|---|
| `question`（原话） | 身份识别、题库指代匹配、追问生成、**落库的 `input_prompt`** |
| `routed_q`（改写后） | 路由分类、检索、作答提示词里的「问题：」 |

为什么分开：多轮里「那它和分类分级是什么关系」不改写会被判成 `off_topic` 直接拒答；但学生原话必须原样留档，否则复盘时看不到他真正说了什么。

改写只在需要时发生（`rag/enhance.py:89`），且实测不丢细节：一句带「三个月问卷 / 妇科产科儿科 / 年底交初稿」的 61 字追问，改写后六个条件全部保留。

## 3. 八条作答路径

| 路径 | 触发 | 模型调用 | 核心做法 |
|---|---|---|---|
| `course` 课程 | 数据要素概念 | 4 次 | 四步管线：LLM 选概念 → 确定性召回 → LLM 逐块定级 → 作答 |
| `thesis` 论文 | 选题/开题/方法 | 2–4 次 | 检索纠错 + 可选子问题拆分；检索总轮数默认 2、硬上限 3 |
| `policy` 政策 | 法条、适用范围 | 2–3 次 | 点名直达 → BM25 初筛 → 模型选块 → 作答（**不用向量库**） |
| `case` 判例 | 具体案件 | 2 次 | 卡片召回 + 最相关正文块 |
| `quote` 讲话 | 总书记表述 | 1–2 次 | **原文照录不改写**，模型只能标 `[Q#]`，程序贴原文 |
| `exam` 试题 | 找题 / 出题 | 0–1 次 | 预匹配命中即零调用；另接 `POST /exam/grade` 判分 |
| `combined` 组合 | 一次问多个库 | 各库并行 + 1 次 | 分区分 `[S1][C1][Q1][P1]`，**只写一次**作答 |
| `off_topic` 库外 | 超出知识库 | 1 次 | 大模型自身知识答，明确标注「非知识库内容」 |
| `meta` 助手自身 | 见下 | **0 次** | 程序直接回，不检索不调模型 |

组合路由只允许 `course / case / quote / policy` 之间两两组合；出现 `thesis / exam / off_topic` 就不组合，取第一个（`rag/router.py:110`）。

### `meta` 的六种问法（全部零调用）

| 问法 | 回答 |
|---|---|
| 纯打招呼（「你好」） | 一句欢迎语 + 两三个例子 |
| 确认 / 收尾（「好的 了解了」「谢谢」） | 一句短的；有上文时带上上一轮的具体概念 |
| 问刚才怎么答的（「你的回答链路是怎样的」） | 讲本轮实际路径，不背能力清单 |
| 问我是谁（「我是谁」「你记得我是谁」） | 回学生档案：身份 + 学校 + 论文题目 + 主题 + 交过的题 |
| 问之前问过什么 | 按 `qa_log` 列本人提问 |
| 问能力 / 知识库 | 按实际加载的库列清单 |

「我是谁」与「你是谁」必须分开：前者问学生自己，后者问助手。

## 4. 检索技术栈

### 4.1 论文库（通用 RAG）

- 稠密：BGE-m3（`BAAI/bge-m3`）
- 稀疏：BM25（jieba 分词，磁盘缓存）
- 融合：RRF
- 重排：`BAAI/bge-reranker-v2-m3`，本机无 GPU **默认关闭**
- 分块：600 字 / 重叠 100；`TOP_K=4`

### 4.2 课程库（做深了的那一个）

**Step 1 选概念**：LLM 工具调用循环，工具为 `search_vocab / get_concept / get_neighbors / finish`。有 `max_steps` 上限，用完强制 finish；较早轮次的工具返回压缩成只剩 ID 与名称，避免输入 token 持续增长。

**Step 2 召回（确定性，不用模型）**：概念 → 本体边证据（`P####` 锚点）→ 教材段落 → 子块。按可信度分 4 档：

```
tier 0  教材证据可核实 + 专家来源
tier 1  教材证据可核实 + 机器来源
tier 2  未核实（含 section_first 下沉）
tier 3  mention（字面提及）
```

参考文献 / 前言 / 空段 / 越界锚点会被排除并记录，**绝不静默丢弃**。

**Step 3 筛选**：逐块定级 `direct / background / irrelevant`，只回编号不写理由（逐块写理由约 0.4s/块，基本都花在生成理由上）。召回块不多于阈值时整步跳过。

**Step 4 作答**：先 `direct` 后 `background`，同级按相关分排序，**最多 10 块**。这个 10 是评测调出来的：15 块与 10 块在 24 个参考块上保留数相同，8 块会丢一个。

### 4.3 政策库

不走向量库，启动时直接读原始 docx 建索引。三级定位：

1. 点名直达（程序）：出现文件名 / 简称 / 别名（含「数据二十条」）→ 锁定文件；同时问「第X条」→ 直接取该条
2. BM25 初筛最多 15 块；提到北京 / 上海 / 广东 / 贵州等地时先限定地区，不够再放宽
3. 模型选块最多 6 个编号；都不相关则给改写词，只重查一次；仍没有 → `not_found`，不调作答

模型写在引号里的法条文字必须逐字出自入选块，否则删除引号内容、保留 `[n]`；征求意见稿由程序标注「非正式生效文本」。

## 5. 提示词分层

```
persona.py              角色卡（单一来源，六个库都 import）
  ├ PERSONA_CORE        人设：AI 李老师，数字治理科研团队的学术数字人
  ├ BOUNDARY            能答的范围
  ├ RED_LINES           四条跨库红线：
  │                       不编出处 / 不把库外常识说成原文 /
  │                       资料不足就明说 / 不写套话式免责
  ├ GREETING_SHORT      纯打招呼的短回复
  └ EXAMPLE_DIALOGUE    多轮接话示例（示范「接话」）
        │
prompt_rules.py         应答格式 + few-shot 样例（集中管理）
  └ ANSWER_STRUCTURE    按问法分流：
                          定义 / 是非 / 单概念说明 → 不分点，150–250 字
                          列举 / 关系 / 区别 / 原因 / 作用 → 总—分—总，≤400 字
        │
各库 _SYSTEM_PROMPT     本库专属规则（论文库已去掉课程格式，改问题驱动）
        │
with_history()          历史原样插在 system 与 user 之间；
                        画像追加到 system 末尾（不进 user，否则模型以为是学生说的）
```

最终形状：

```
[system: 角色卡 + 本库规则 + 格式 + 样例 + 画像]
[user1][assistant1][user2][assistant2]
[userN: 问题 + 材料]
```

有一条测试强制 `s.count("你是 AI 李老师") == 1`，防止人设被写第二遍。

各库 `user` 消息的形状：

| 库 | 形状 | 编号 |
|---|---|---|
| 课程 | `问题：X\n\n【教材原文】\n[S1] 路径\n正文` | `[S1]` |
| 政策 | `问题：X\n\n政策条文材料：\n[P1] 篇›文件名›第X条\n正文` | `[P1]` |
| 判例 | `学生问题：X\n\n判例材料：\n[C1] …` | `[C1]` |
| 组合 | 分区：`【教材材料】`→`【判例材料】`→`【讲话原文】`→`【政策条文】` | `[S#][C#][Q#][P#]` |
| 论文 | `资料：\n[1] 来源（章节）\n正文\n\n问题：X` | `[1]` |
| 库外 | 纯问题，不检索 | 无 |

## 6. 三层记忆

| 层 | 存储 | 记什么 | 谁在用 |
|---|---|---|---|
| 短记忆：会话 | `conversations.sqlite3` | 逐轮 user / assistant，**送模型只取最近 6 轮 / 8000 字** | 多轮上下文 |
| 长记忆：前情 | `conversations.recap` | 超出窗口的旧轮次压成 2–3 句 | 每轮与画像一起注入 system |
| 审计 | `qa_log.sqlite` | 原话、路由、来源、token、耗时、system 提示词哈希 | 复盘、评测、`/v1/conversations` |
| 长记忆：学习画像 | `profile.sqlite` | 见下 | 每轮注入提示词 |

### 短记忆与长记忆之间：前情摘要（`rag/recap.py`）

不补这一层的话，一个 19 轮的会话，前 13 轮模型完全看不见——学生问「前面那个抽样方案」，
它只能答「你说的是哪个」。画像补不了这个缺口：画像只记「问过哪些概念」，不记「聊到哪儿了、定了什么」。

```
第 1–3 轮  → 原文进 recap（压缩后）
第 4–k 轮  → 原文进模型（最近 6 轮）
第 k+1 轮  → 只进模型，不进 recap
```

- **增量**：已摘到第 `recap_upto` 轮，只把之后的新轮次补进去，旧摘要作为上下文一起给模型合并。
  不是每轮重摘全量——19 轮的会话只多两次小调用。
- **推进量按实际覆盖轮次算**，不用「总轮数 − 窗口」推算：预算截断时两者不一致，会重复摘同一段。
- **只保留能承接对话的东西**：在做什么题、卡在哪一步、定了什么决定、明确的限制与偏好。
  不写客套、过程、对学生的评价（「基础较弱」这类）——与画像同一条原则。
- **失败静默**：模型未配置 / 超时 / 写库失败都保留旧摘要，本轮回答照常返回，下一轮再补。
- **短会话不受影响**：没超出窗口时返回空串，提示词逐字不变。

### 学习画像的四张表

```
learner_profile   学校 / 学历 / 专业 / 学科门类 / 论文阶段 / 论文题目
learner_concept   问过的概念、次数、首次与最近时间
learner_chapter   关注过的章、次数
learner_mastery   题号、章、概念、1–5 分、是否答对、判分方法
```

**设计原则：只记能解释来源的事实，不做推断。**

- 判分只在学生**真的提交了答案**之后才写；没提交就没有记录，不猜「他大概不会」
- 「还没答对」只按**同一道题重做答对**消除，不做时间衰减——没有依据的遗忘曲线等于编数据
- 只取问过 **两次以上** 的概念：课程管线一次会选出 6–8 个概念，全列出来等于把词表塞进提示词
- 没有记录时提示词**逐字不变**，不会出现编造的「我记得你」
- 每人上限 8 概念 / 5 章 / 50 条判分记录，写失败只记 warning，绝不影响主请求

注入的那一句话长这样：

```
【这个学生的情况】内蒙古大学，硕士生，公共管理专业；论文题目：妇幼保健院门诊患者满意度研究；
之前问过：数据确权、数据资产；做过题但还没答对：数据资产。
回答时按他的专业与阶段举例选材，不要生硬复述、不要推断他的水平；他说过的题目要按原题理解，不要改写。
```

### 身份与题目怎么认

`rag/student.py`，**只认明确说法，不猜**：

- 学校：先把校名摘出单独存，否则「内蒙古大学公共管理专硕」会把专业记成「内蒙古大学公共管理」
- 学历 / 专业 / 学科 / 阶段：`我是…本科生`、`…专业`、`论文在选题阶段`
- 论文题目：只认显式说法（「论文题目是…」「在做…的研究」）或整句就是题目的情形（以「研究 / 分析 / 调查 / 对策」收尾、可带「——以…为例」），**不从句子中间猜**——猜错一次，之后每轮都会引用一个学生没写过的题目
- `only_intro`：句子短、没疑问、不带要处理的内容才算纯自述。带论文题的长句只记录身份，按原问题作答（此前整句被吞成「记住了：硕士生」）

## 7. 接口面

| 分组 | 端点 |
|---|---|
| 统一入口 | `POST /auto/ask`、`POST /auto/ask/stream`（SSE） |
| 论文库单轮（兼容旧前端） | `POST /ask`、`POST /ask/stream` |
| OpenAI 兼容 | `POST /v1/chat/completions`、`GET /v1/models` |
| 会话管理 | `GET/POST /v1/conversations`、`GET/DELETE /v1/conversations/{id}`、`GET/DELETE .../messages` |
| 试题 | `POST /exam/search`、`POST /exam/by_concepts`、`POST /exam/grade`、`GET /exam/question/{id}` |
| 课程单库 | `POST /course/ask` |
| 健康 | `GET /health` |

全部走 `Authorization: Bearer <key>`；`API_KEYS` 支持多个 key 逗号分隔。

### 流式事件

```
route → stage(select/filter) → materials → delta… → done → followups
```

- `materials` 在某块第一次被引用（分配序号）时发出
- `followups` 在 `done` **之后**单独一帧，不阻塞主答案
- 出错发 `error`

### 会话归属

会话按 `(key, uuid)` 归属。共用一把 key 时学生之间互不可见——写会话时会校验 `user_id`，别人的会话写不进来。

## 8. 工程约束（这些是有意为之，不是没做）

**引用改写**：模型写 `[S1]`，`CitationRewriter` 按首次出现重编成 `[1][2]`；不在材料里的编号直接删并计入 `invalid_citations`；凭空写的 `[本体]` 也删；`[S12]` 被切在两个流式分片之间时先缓冲到闭合，避免正文漏出半个括号。

**失败不伪装**：

- 判分失败给 `not_found / empty_answer / no_reference`，**不编 0 分**
- 资料不足返回 `insufficient`，不编答案
- 课程三个回退码：`no_valid_concepts` / `no_recall` / `all_filtered_out`

**降级**：任一库加载失败只影响该库（`_route_ready` 判定），能力清单按实际可用项列，不列没有的库。

**讲话原文不可改写**：模型只能写 `[Q#]` 标记；程序在回答末尾按「讲话原文」分区**原样贴出**所引段落。模型输出里若出现引号内的讲话文字，逐字核对挑出的原文，不一致就整段删除。

**并发**：不再持全局检索锁。encode 走 BatchedEmbedder（线程安全、成批编码），Chroma `query()` 与 BM25 `search()` 都是只读，可并发（实测 8 并发共 6.7ms）。此前锁把整段检索串起来，长问题（2600 字 embed 2.7s）会堵住后面的所有请求。

## 9. 已知限制

1. **`/auto/ask` 的 `question` 上限 500 字**（`rag/unified.py:47`）。超出返回 422，而前端 `textarea` 没有任何长度提示，只会显示「请求失败（HTTP 422），请重试」。论文场景里粘一段开题初稿（562 字）就会撞上，且看不到真实原因。
2. **`/v1/chat/completions` 只覆盖论文库**。要全库能力必须用 `/auto/ask`。
3. **`/v1` 的 `usage` 恒为 0**，未接 tokenizer。
4. **检索不跨轮**：只用本轮（或改写后）的问题，历史仅作为作答上下文。多跳问题需要用户自己说清楚。
5. **课程材料不做摘要压缩**，原文切片直入提示词。好处是引用能逐字对上，代价是 10 块是硬上限。
6. **身份识别只认明确说法**：说「我学出版的」认不出「专业」这个词就不记。宁可少记，也不给学生安一个没说过的身份。
7. **`/ask`、`/ask/stream` 不支持会话**，是论文库单轮接口，保留只为兼容旧前端。

## 11. 演进记录（按主题）

| 主题 | 做了什么 |
|---|---|
| 多库统一 | 六库共用一个入口，LLM 路由 + 规则兜底；组合路由支持一次问多个库 |
| 问答记录 | `qa_log` + `prompts` 去重，WAL，写失败隔离；按 `(uuid, 姓名)` 归属 |
| 会话隔离 | 会话按 `(key, uuid)` 归属，共用 key 时学生互不可见 |
| 角色卡 | 人设从 6 处收敛到 `persona.py` 一份，测试强制不重复 |
| 回答不死板 | 思考模式从 `disabled` 改回 `low`；格式从「一律总—分—总」改为按问法分流；确认语带上上一轮的具体概念 |
| 学习者画像 | 从「问过什么」到「哪里没答对」，判分闭环接进产品链路 |
| 理解用户 | 自述身份不再被当问题答；记住学校与论文题目；「我是谁」回档案而不是助手介绍 |
